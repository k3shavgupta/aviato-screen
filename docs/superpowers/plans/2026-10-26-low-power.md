# Low-power dashboard implementation plan

**Goal:** Implement the approved dashboard optimizations while preserving its appearance and server workloads.

**Architecture:** Keep one native C process and direct framebuffer output. Use independent monotonic refresh deadlines, bounded reusable HTTP responses, sampled system readings, and region comparisons. Treat media/remote control and authenticated portfolios as subsequent integrations.

**Tech stack:** C, gcc, existing libcurl runtime, stb_truetype, Linux framebuffer/systemd.

## Constraints and workspace

The application folder is ignored by an unrelated Git repository rooted at the user's home. Work in the current application folder, preserve the original source and executable in `backups/2026-10-26-low-power/`, and do not change the home repository or its ignore rules. The baseline builds with `gcc -O2 -Wall -Wextra -o /tmp/aviato-screen-baseline aviato-screen.c -lm /usr/lib/x86_64-linux-gnu/libcurl.so.4`.
